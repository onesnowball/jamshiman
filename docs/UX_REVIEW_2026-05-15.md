# UX review — 2026-05-15

Targeted review of jamshiman's primary user flows from a code reading
(no live browser, no Preview MCP — see CLAUDE.md notes). Findings are
ranked by impact, not by file order.

Each item: **what's confusing**, **why it matters**, **suggested fix**.
Tags: `[P0]` blocks the flow, `[P1]` real friction, `[P2]` polish.

---

## 1. New-user redirect chain — login → boards → onboarding `[P1]`

**Where:** [`app/auth/login/page.tsx:121`](app/auth/login/page.tsx:121), [`app/[school]/layout.tsx`](app/[school]/layout.tsx)

After OTP verification + handle setup, login forces `window.location.href = '/{slug}/boards'`. But the school layout then redirects an un-onboarded user to `/profile/onboarding`. So the first-time user sees: **login → boards page flash → onboarding page**. Two redirects, brief flash of content they shouldn't see.

**Fix:** in login, after `/api/auth/setup` succeeds, send users straight to `/profile/onboarding` if `needsOnboarding` is true (and add that flag to the setup API response). Boards-as-default is fine for returning users.

---

## 2. Handle setup screen is redundant for new users `[P1]`

**Where:** [`app/auth/login/page.tsx:188`](app/auth/login/page.tsx:188), [`components/profile/GradOnboardingForm.tsx`](components/profile/GradOnboardingForm.tsx)

The login flow has its own "Choose a display name" step (with a "Skip for now" button). The onboarding page **also** collects a handle. New users will hit handle setup twice.

**Fix:** drop the handle step from the login flow entirely. Let onboarding own it. The `/api/auth/setup` route can stop returning `needsHandle`. Returning users keep their existing handle.

---

## 3. School dashboard says "Welcome back" to brand-new users `[P2]`

**Where:** [`app/[school]/page.tsx:86`](app/[school]/page.tsx:86)

Heading reads "Welcome back" unconditionally. A user landing here for the first time after onboarding sees that and reasonably wonders "back from where?".

**Fix:** check `users.created_at` against now; show "Welcome to {school}" if account < 24h old, "Welcome back" otherwise. Or use a single neutral phrase.

---

## 4. Recent posts on school home don't actually link to the post `[P1]`

**Where:** [`app/[school]/page.tsx:171-173`](app/[school]/page.tsx:171)

The "Recent board posts" list on the school dashboard renders each post as a `<Link href={'/${school}/boards'}>` — i.e., to the boards index, not the post detail. User clicks a title expecting to read it, lands on the boards listing, has to find it again.

**Fix:** link each item to `/{school}/boards/{deptSlug}/{post.id}`. Requires joining `departments.slug` into the query (already partially there via `dept_id`).

---

## 5. Pulse is invisible on the school dashboard `[P1]`

**Where:** [`app/[school]/page.tsx`](app/[school]/page.tsx), Pulse appears in [`components/NavbarClient.tsx`](components/NavbarClient.tsx) but isn't surfaced anywhere else.

The whole differentiator of jamshiman post-Pulse-V1 is the daily check-in habit. But the school home has zero mention of it — no "you haven't checked in today" prompt, no card, nothing. New users have to discover Pulse via the nav icon.

**Fix:** add a "Today's pulse" card near the top of the school home that:
- says "Check in to see today's stats" if not checked in
- shows a small recap if checked in (a single rolling number, e.g. avg sleep)
- always links to `/{school}/pulse`

## 6. New-post form silently disables Post button without explaining why `[P2]`

**Where:** [`components/boards/NewPostForm.tsx:87`](components/boards/NewPostForm.tsx:87)

Submit is disabled when `title.trim().length < 4 || body.trim().length < 10`. No hint. User types a 3-character title and sees the button greyed out with no idea why.

**Fix:** show a tiny helper line: "Need at least 4 characters in the title and 10 in the body." Or live character count under each field.

---

## 7. New-post form defaults to the first department, which is invisibly "General" `[P2]`

**Where:** [`app/[school]/boards/new/page.tsx:38-42`](app/[school]/boards/new/page.tsx:38), [`components/boards/NewPostForm.tsx:13`](components/boards/NewPostForm.tsx:13)

The parent sorts board categories first (General at the top), so the select defaults to a `<option value=General-id>General</option>`. User who came from `/umich/departments/me` to post about MechE could miss that and post in General by accident.

**Fix:** if the user navigated from a specific department page, default the select to that dept (pass via search param `?dept=mechanical-engineering`). Otherwise, prefix board categories with "📣" or similar in the dropdown so the visual hierarchy is obvious.

## 8. Skip-handle option in login lets users into the app with no handle `[P2]`

**Where:** [`app/auth/login/page.tsx:154-157`](app/auth/login/page.tsx:154)

`skipHandle()` redirects to /{slug}/boards with no handle set. Then they hit the onboarding redirect (good), but the onboarding form pre-populates handle from `currentHandle` which is null, so they're forced to type one anyway. The "Skip for now" affordance is misleading because it can't actually be skipped.

**Fix:** remove "Skip for now" once #2 is done (handle setup moves to onboarding, where it's required).

---

## 9. Onboarding has no back-out for already-signed-in but un-onboarded users `[P2]`

**Where:** [`app/profile/onboarding/page.tsx`](app/profile/onboarding/page.tsx)

If someone signs in and decides "actually I don't want to do this right now", every route bounces them back to /profile/onboarding. There's no "sign out from this screen" option. They have to know to go elsewhere first.

**Fix:** add a tiny "Sign out" link at the bottom of the onboarding page. We have `SignOutButton` from yesterday; reuse it.

---

## 10. "Verified students only · Anonymous by default · Moderated for safety" appears everywhere but explains nothing `[P2]`

**Where:** [`app/[school]/page.tsx:234`](app/[school]/page.tsx:234), [`app/[school]/advisors/[id]/page.tsx:215`](app/[school]/advisors/[id]/page.tsx:215), and elsewhere.

The phrase reassures, but a first-time grad student might wonder: "What does *moderated* mean? Will my review get rejected? Who decides?". The promise is repeated everywhere but never linked to a real explanation.

**Fix:** wrap the phrase in a small `<Link href="/about/safety">` (or a tiny popover) with a 3-paragraph plain-English explanation: how anonymity works, how moderation works, what happens if you get flagged. Same content surfaced from multiple places.

## 11. Advisor "Request a review" button has no public-facing explanation `[P2]`

**Where:** [`components/advisors/AdvisorReviewRequestButton.tsx`](components/advisors/AdvisorReviewRequestButton.tsx)

A grad student who's never used jamshiman before sees an advisor with no reviews and a "Request a review" button + count. Unclear what *they* get out of pressing it, or who fulfills the request.

**Fix:** put a one-line description above the button on the empty state, like "Future students with this advisor will see how many people want a review. We won't email anyone — this just shows demand."

---

## 12. Lurker capybara can overlap with bottom-anchored UI on small screens `[P2]`

**Where:** [`components/brand/CapybaraLurker.tsx`](components/brand/CapybaraLurker.tsx)

Lurker is fixed at `bottom-0 right-0` with a 360px-wide zone. On phones (≤375px) the capybara walking can overlap board-post compose buttons, the FlagButton dropdown, or footers. Also doesn't respect safe-areas on iOS.

**Fix:** hide on small screens (`md:` breakpoint), or shrink to 56px in the corner only, or move above the iOS home indicator with `padding-bottom: env(safe-area-inset-bottom)`.

---

## 13. Pulse check-in form: "Hours worked" + "Coffees/teas" are buried in `<details>` without preview `[P2]`

**Where:** [`components/pulse/DailyCheckInCard.tsx`](components/pulse/DailyCheckInCard.tsx)

The optional fields live inside a `<details>` block labeled "Optional context (skip if you want)". Good for cleanliness, but a new user might miss them entirely and never log caffeine even if they wanted to.

**Fix:** mention them on the closed summary: "Optional: hours worked, caffeine, late-night flag, context tag". One extra line, big clarity win.

---

## 14. Anonymity wording is inconsistent across surfaces `[P2]`

Three different phrasings of the same idea exist:
- "Verified .edu only · Anonymous by default · No passwords" (landing)
- "Verified students only · Anonymous by default · Moderated for safety" (school home)
- "Your identity is not shown publicly. Avoid details that could identify you or others." (course review form)
- "Reviews stay anonymous and only appear in aggregate once privacy thresholds are met." (advisor empty state)

**Fix:** pick one canonical phrasing for the trust footer ("Verified students. Anonymous by default. Moderated.") and use a single component to render it everywhere. Variations are fine in form contexts.

---

## 15. There's no path to delete the account `[P1]`

There's a sign-out button (added yesterday) but no "Delete my account" anywhere I can find. Posts/comments can request delete, but the account itself can't.

**Fix:** add a "Request account deletion" row on `/profile`, behind a confirmation modal. Wire it to email an admin or set a `users.delete_requested_at` column for now. Important for GDPR/CCPA posture even at beta scale.

## What I did NOT review

- The admin/moderation flows (out of scope for normal-user UX).
- Mobile-specific layout issues beyond #12 (no way to verify without a live browser).
- Accessibility (color contrast, screen reader labels, keyboard nav) — needs a focused pass with axe-core or similar.
- Performance / loading state UX on slow networks.

---

## Suggested order of attack

If you only do four things, do these:
1. **#1 + #2 together** — kill the handle setup screen, send new users directly to onboarding. Single biggest first-time friction.
2. **#5** — surface Pulse on the school home. Pulse is the differentiator; hiding it in nav undersells it.
3. **#4** — fix the recent-posts links so they actually link to the post.
4. **#12** — phone-screen lurker overlap, before any of your beta users open it on iOS.

The rest can wait.
